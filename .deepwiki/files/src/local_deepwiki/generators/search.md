# File: `src/local_deepwiki/generators/search.py`

## File Overview

This module is responsible for generating a JSON search index that enables client-side full-text search across wiki documentation. The index includes both page-level entries (from markdown content) and entity-level entries (from code chunks such as functions, classes, and methods).

The design rationale is to provide a lightweight, client-side search solution that can be used without external dependencies or server-side processing. The search index is generated by parsing wiki pages and code chunks, extracting meaningful content, and structuring it into a searchable format.

## Key Concepts

### Search Index Structure
The search index is structured as a dictionary with two main components:
- `pages`: Page-level entries that include headings, code terms, and snippets for full-text search.
- `entities`: Entity-level entries for code constructs (functions, classes, methods) with metadata such as type information, signatures, and exceptions.

### Content Extraction
Several helper functions are used to extract meaningful content from markdown and code:
- `extract_headings`: Extracts heading text from markdown.
- `extract_code_terms`: Identifies code terms from inline code blocks.
- `extract_snippet`: Generates a plain text snippet for preview.

These functions use regular expressions to parse content, with care taken to avoid extracting overly long or complex code snippets.

### Entity Metadata Handling
Entity-level search entries are built from [`CodeChunk`](../models/chunks.md) objects, which contain metadata such as:
- [Parameter](analysis/api_docs.md) types
- Return types
- Exception types (`raises`)
- Async status

The `_build_keywords` function aggregates these into a searchable list of terms, splitting names and types into meaningful parts.

### Asynchronous Processing
The module uses asynchronous functions (`generate_entity_entries`, `generate_full_search_index`, `write_full_search_index`) to allow for efficient processing of large codebases, particularly when interacting with a [`VectorStore`](../core/vectorstore/store.md) to retrieve code chunks.

## Integration

This module integrates with the following components:

- **[`VectorStore`](../core/vectorstore/store.md)**: Used to retrieve [`CodeChunk`](../models/chunks.md) objects for entity-level search entries. The `generate_entity_entries` function fetches chunks by file path and processes them into structured search entries.
- **[`IndexStatus`](../models/wiki.md)**: Provides information about which files need to be indexed, used in `generate_entity_entries` to iterate over files.
- **[`WikiPage`](../export/streaming.md)**: Represents markdown content that is processed into page-level search entries via `generate_search_index` and `generate_search_entry`.
- **CLI Tools**: The `write_full_search_index` function is used by CLI commands to generate and persist the search index to disk.

The module is called by `test_search`, indicating it is a core part of the system's testing suite, ensuring search functionality works correctly across both pages and code entities.

## Design Notes

### Why JSON?
The search index is stored as JSON to ensure compatibility with client-side JavaScript-based search implementations. It avoids the need for a database or complex server-side logic, enabling simple static file serving.

### Handling Code Terms
The `extract_code_terms` function filters out long or multi-line code snippets to avoid indexing noisy or unhelpful content. It also extracts qualified names (e.g., `module.Class.method`) and their last components for better search coverage.

### Entity Signature Building
The `_build_entity_signature` function provides a concise preview of function signatures, limiting parameters to the first three and truncating long lists. This helps with search result clarity and performance.

### Keyword Generation
The `_build_keywords` function is designed to extract meaningful search terms from entity metadata:
- Names are split by underscores and camelCase for better matching.
- Type information is normalized by extracting base types (e.g., `list[str]` → `list`).
- Exception names are normalized to remove the "Error" suffix for easier discovery.

### Asynchronous Workflow
The use of `async` functions ensures that the search index generation does not block the main thread, particularly when retrieving data from a [`VectorStore`](../core/vectorstore/store.md), which may involve disk or network I/O.

### Edge Cases
- Empty or malformed docstrings are handled gracefully in `_build_entity_description`.
- Long snippets are truncated with an ellipsis (`...`) to prevent oversized index entries.
- Code terms with spaces or full statements are filtered out to avoid indexing non-meaningful content.

def extract_headings(content: str) -> list[str]:
    """Extract all headings from markdown content.

    Args:
        content: Markdown content.

    Returns:
        List of heading texts (without # prefixes).
    """
    headings = []
    for line in content.split("\n"):
        line = line.strip()
        if line.startswith("#"):
            # Remove # prefix and clean up
            heading = re.sub(r"^#+\s*", "", line)
            # Remove markdown formatting like ** or `
            heading = re.sub(r"[*`]", "", heading)
            if heading:
                headings.append(heading)
    return headings

def extract_code_terms(content: str) -> list[str]:
    """Extract code terms (class names, function names) from content.

    Args:
        content: Markdown content.

    Returns:
        List of code terms found in backticks.
    """
    terms = set()
    # Match inline code: `term`
    for match in re.finditer(r"`([^`]+)`", content):
        term = match.group(1)
        # Skip code that looks like a full statement or has spaces
        if len(term) < 50 and "\n" not in term:
            # Extract the main identifier if it's a qualified name
            parts = term.split(".")
            if parts:
                terms.add(parts[-1])  # Last part of qualified name
            if len(parts) > 1:
                terms.add(term)  # Also add full qualified name
    return list(terms)

```python
def extract_snippet(content: str, max_length: int = 200) -> str:
    """Extract a text snippet from markdown content.

    Args:
        content: Markdown content.
        max_length: Maximum snippet length.

    Returns:
        Plain text snippet.
    """
    # Remove code blocks
    text = re.sub(r"```[\s\S]*?```", "", content)
    # Remove headings
    text = re.sub(r"^#+\s+.*$", "", text, flags=re.MULTILINE)
    # Remove links but keep text: [text](url) -> text
    text = re.sub(r"\[([^\]]+)\]\([^)]+\)", r"\1", text)
    # Remove markdown formatting
    text = re.sub(r"[*_`]", "", text)
    # Collapse whitespace
    text = " ".join(text.split())

    if len(text) > max_length:
        text = text[:max_length].rsplit(" ", 1)[0] + "..."

    return text.strip()
```

async def generate_entity_entries(
    index_status: IndexStatus,
    vector_store: VectorStore,
) -> list[dict]:
    """Generate search entries for individual code entities.

    Creates searchable entries for each function, class, and method
    with type information for filtering.

    Args:
        index_status: Index status with file information.
        vector_store: Vector store with code chunks.

    Returns:
        List of entity search entries.
    """
    entries: list[dict] = []

    for file_info in index_status.files:
        chunks = await vector_store.get_chunks_by_file(file_info.path)
        for chunk in chunks:
            if chunk.chunk_type not in _ENTITY_CHUNK_TYPES:
                continue
            entries.append(_chunk_to_entity_entry(chunk, file_info.path))

    return sorted(entries, key=lambda e: e["display_name"].lower())

async def generate_full_search_index(
    pages: list[WikiPage],
    index_status: IndexStatus | None = None,
    vector_store: VectorStore | None = None,
) -> dict:
    """Generate a comprehensive search index with pages and entities.

    Args:
        pages: List of wiki pages.
        index_status: Optional index status for entity extraction.
        vector_store: Optional vector store for entity extraction.

    Returns:
        Dictionary with 'pages' and 'entities' lists.
    """
    page_entries = generate_search_index(pages)

    entity_entries: list[dict] = []
    if index_status and vector_store:
        entity_entries = await generate_entity_entries(index_status, vector_store)

    return {
        "pages": page_entries,
        "entities": entity_entries,
        "meta": {
            "total_pages": len(page_entries),
            "total_entities": len(entity_entries),
        },
    }

def _build_entity_signature(
    entity_type: str,
    param_types: dict,
    return_type: str | None,
) -> str:
    """Build a short signature preview string for an entity."""
    if entity_type == "class":
        return ""
    params = list(param_types.keys())[:3]
    if len(param_types) > 3:
        params.append("...")
    sig = f"({', '.join(params)})"
    if return_type:
        sig += f" → {return_type}"
    return sig

def _chunk_to_entity_entry(chunk: CodeChunk, file_path: str) -> dict:
    """Convert a single code chunk to a search entity entry dict."""
    entity_type = chunk.chunk_type.value  # 'class', 'function', 'method'

    if chunk.chunk_type == ChunkType.METHOD and chunk.parent_name:
        display_name = f"{chunk.parent_name}.{chunk.name}"
    else:
        display_name = chunk.name or "Unknown"

    metadata = chunk.metadata or {}
    param_types = metadata.get("parameter_types", {})
    return_type = metadata.get("return_type")
    raises = metadata.get("raises", [])
    is_async = metadata.get("is_async", False)

    wiki_path = f"files/{file_path}".replace(".py", ".md")

    return {
        "type": "entity",
        "entity_type": entity_type,
        "name": chunk.name or "Unknown",
        "display_name": display_name,
        "path": wiki_path,
        "file": file_path,
        "signature": _build_entity_signature(entity_type, param_types, return_type),
        "description": _build_entity_description(chunk.docstring),
        "is_async": is_async,
        "raises": raises,
        "keywords": _build_keywords(chunk.name, param_types, return_type, raises),
    }

```python
def _build_keywords(
    name: str | None,
    param_types: dict[str, str],
    return_type: str | None,
    raises: list[str],
) -> list[str]:
    """Build search keywords from entity metadata.

    Args:
        name: Entity name.
        param_types: Parameter types mapping.
        return_type: Return type string.
        raises: List of exception types.

    Returns:
        List of searchable keywords.
    """
    keywords: set[str] = set()

    # Add name parts (split on underscore and camelCase)
    if name:
        keywords.add(name.lower())
        # Split on underscores
        for part in name.split("_"):
            if len(part) > 2:
                keywords.add(part.lower())
        # Split camelCase
        camel_parts = re.findall(r"[A-Z][a-z]+|[a-z]+", name)
        for part in camel_parts:
            if len(part) > 2:
                keywords.add(part.lower())

    # Add type keywords
    for type_str in param_types.values():
        if type_str:
            # Extract base type (e.g., "list" from "list[str]")
            base_type = re.split(r"[\[\]|,\s]", type_str)[0].lower()
            if base_type:
                keywords.add(base_type)

    if return_type:
        base_return = re.split(r"[\[\]|,\s]", return_type)[0].lower()
        if base_return:
            keywords.add(base_return)

    # Add exception keywords
    for exc in raises:
        keywords.add(exc.lower())
        # Also add without "Error" suffix for easier search
        if exc.endswith("Error"):
            keywords.add(exc[:-5].lower())

    return list(keywords)
```
