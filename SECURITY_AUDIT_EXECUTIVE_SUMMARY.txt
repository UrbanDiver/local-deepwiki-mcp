================================================================================
                          CRITICAL FINDINGS (3)
================================================================================

FINDING 1: API KEY EXPOSURE IN MEMORY
  Severity: HIGH | CVSS: 7.5 | CWE-798
  Location:
    - /src/local_deepwiki/providers/llm/anthropic.py:45
    - /src/local_deepwiki/providers/llm/openai.py:49
    - /src/local_deepwiki/providers/embeddings/openai.py:35

  Problem:
    API keys loaded from environment and stored as instance variables
    Keys remain in memory for provider lifetime
    Accessible via process memory dumps or debugging tools

  Risk:
    - Attacker gains API credentials
    - Can make unlimited API calls at victim's expense
    - Can access all documents via LLM services

  Fix Time: 2-3 hours
  Fix: Implement secure credential manager, pass keys directly to SDK

================================================================================

FINDING 2: ERROR MESSAGE INFORMATION DISCLOSURE
  Severity: HIGH | CVSS: 6.0 | CWE-209
  Location: /src/local_deepwiki/handlers.py:131-135 (main issue)

  Problem:
    Full exception text returned to users
    Reveals internal paths: /home/user/.config/local-deepwiki/...
    Reveals API endpoints: http://localhost:11434/api/chat
    Reveals model information and configuration

  Risk:
    - Attacker maps infrastructure
    - Understands internal architecture
    - May find new attack vectors

  Fix Time: 1-2 hours
  Fix: Sanitize error messages, remove paths and URLs before returning

================================================================================

FINDING 3: NO ACCESS CONTROL LAYER
  Severity: MEDIUM (HIGH in multi-user) | CVSS: 6.5 | CWE-639
  Location: All tool handlers in /src/local_deepwiki/handlers.py

  Problem:
    No authentication or authorization checks
    Any user can access any repository
    Can index sensitive repositories without permission
    No audit trail of who accessed what

  Risk:
    - Unauthorized access to private code
    - Secret exposure (API keys in config files)
    - Compliance violations (HIPAA, GDPR, SOC2)

  Attack Scenario:
    User A: ask_question("/path/to/user-b-private-repo")
    → System returns code from User B's repo without checks
    → User A can extract all secrets

  Fix Time: 3-4 hours
  Fix: Add AccessController with allowlist/denylist
